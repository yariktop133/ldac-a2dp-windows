# Проверка на ноутбуке и сравнение с Alternative A2DP (22.10.2026)

Ноутбук: Windows 11 (сборка 26300), адаптер Bluetooth Intel, наушники JBL Live 780NC. Раньше их обслуживал Alternative A2DP 1.8.3.1 (Luculent Systems). Для теста пользователь отключил Secure Boot и включил тестовый режим (`bcdedit /set testsigning on`); BitLocker на машине выключен. Пакет `LdacA2dp-0.2.295.1846` поставлен `install.cmd` поверх Alternative A2DP.

## Замеры

Звук — одинаковые 20 с нот (`captures/beeps.wav`), проигранные `tools/stand/play-to.ps1` в «Наушники (JBL Live 780NC)», не трогая устройство вывода по умолчанию.

| | Alternative A2DP | LdacA2dp |
|---|---|---|
| Кодек | LDAC 96 кГц / 24 бит, SQ 660 кбит/с | LDAC 96 кГц / 24 бит, ABR между SQ (660) и Q0 (492) |
| Состояние канала | его утилита предупреждает: «Обнаружен высокий уровень задержек при передаче пакетов по Bluetooth… битрейт, превышающий возможности вашей системы» | очередь передачи 0–1 пакет, 0 отброшенных за минуту нот (7111 пакетов) и за 9 минут музыки |
| Устройство в Windows (`tools/stand/endpoint-latency.ps1`) | период 10 мс, буфер общего режима 22 мс, задержку потока не сообщает | то же: период 10 мс, буфер 22 мс, 0 |
| Громкость | программная, отдельно от громкости наушников | абсолютная (AVRCP): ползунок Windows = громкость наушников |
| Процессор | ниже фонового шума машины (~15 %) | то же |
| На слух | — | «так же или лучше» (оценка пользователя) |

Адаптер Intel этого ноутбука держит около 600 кбит/с полезного потока: на SQ очередь растёт, ABR через ~4–8 с опускает до Q0 и затем пробует SQ снова. Переключение шагов LDAC проходит без разрыва. Alternative A2DP остаётся на 660 и сообщает о задержках.

Сравнение по событиям HCI «Number Of Completed Packets» не получилось: без полного журнала `btvs` (а он требует записи ключей шифрования в ETW, это мы на хосте не включаем) стек отдаёт единичные события.

## Поведение

- **Сон.** На этой машине есть только Modern Standby (S0 Low Power Idle). За 66 с сна связь с наушниками не рвётся. После пробуждения звук идёт сразу, без нового согласования, громкость прежняя.
- **Расстояние.** В доме 10×10 м связь не рвётся даже в противоположном углу второго этажа. 9 минут музыки: SQ/Q0, 520–640 кбит/с в эфире, 0 отброшенных.
- **Выключение наушников во время музыки** вместо выхода из зоны связи:
  - разрыв замечен сразу; 48 пакетов, бывших в полёте, драйвер отметил как неудачные;
  - пока наушники выключены, служба их не вызывает;
  - после включения поток поднят наушниками в ту же секунду, AVRCP и абсолютная громкость восстановлены.
- **Установка поверх Alternative A2DP.** Наш INF привязан к полному ID наушников и выигрывает у общего ID Alternative A2DP. При удалении нашего пакета наушники возвращаются на Alternative A2DP, он остаётся в хранилище драйверов.

## Инструменты

- `tools/stand/play-to.ps1 -Wav file -Match name` — проигрывает WAV в устройство по имени (общий режим, Windows сама приводит формат); есть пауза на ходу.
- `tools/stand/endpoint-latency.ps1 -Match name` — период устройства и задержка потока общего режима.
- `tools/hci/nocp.py` — темп передачи по событиям «Number Of Completed Packets» из записи `btvs`; на хосте без полного журнала этих событий мало.

## Итог

По решению пользователя на ноутбуке остаётся LdacA2dp, поэтому тестовый режим остаётся включённым, а Secure Boot — выключенным, пока драйвер подписан тестовым сертификатом. Вернуть Alternative A2DP можно так: «Параметры → Приложения → LDAC A2DP → Удалить», затем `bcdedit /set testsigning off` и включить Secure Boot в UEFI.
